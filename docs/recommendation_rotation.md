# 추천 목록의 상위 노출 순환

`POST /api/recommend/next`에 적용한다. 카테고리, 선택 장소 중복, 카테고리별 방문 수, 최초 출발지 도보 20분을 먼저 확인한다. 사용자가 고정한 순서는 변경하지 않는다. 평점·리뷰·가중치는 사용하지 않는다.

총 여행시간은 경고 기준이다. 설정값은 30~360분을 유지하되, 체류·도보·출발지 복귀를 합한 일정이 이를 초과해도 선택·확정·재계산·메일 링크 재열기를 허용한다. 후보 카드와 전체 요약에 설정 시간 및 초과 시간을 표시한다. 시간 내 후보를 먼저 배치하고, 빈자리를 초과 후보로 채우며 각 그룹 안에서 노출 순환을 적용한다. 자동 코스 초안 API는 기존 시간 내 자동 구성 방식을 유지한다.

기존 가까운 후보 최대 20곳을 대상으로 실제 도보 경로를 확인한다. 마지막 선택 장소(없으면 출발지)에서 가장 가까운 적합 후보보다 120초 이내로 더 걸리는 후보끼리 최근 7일 1위 노출 횟수, 전체 목록 노출 횟수, 실제 도보 초, 장소 ID 순으로 정렬한다. 최대 3곳을 보여주며 그룹이 작으면 나머지 적합 후보를 가까운 순으로 채운다. 전체 명부를 대상으로 한 공정성이나 최적 코스를 보장하지 않는다. 후보가 3곳이어도 실제 도보시간을 확인할 때까지 20곳을 조회하므로 기존보다 TMAP 호출이 늘어날 수 있다.

응답의 `recommendation_id`는 서버가 발급한 목록 ID이다. 프런트엔드는 목록 영역이 화면에 보이고 문서가 활성 상태일 때 `/api/recommend/impressions`로 ID를 보낸다. 서버는 자신이 발급한 목록만 인정하고 같은 ID를 한 번만 집계한다. 카테고리 재요청은 새 목록이며, 재렌더링은 같은 목록이다. 목록 표시 실패나 확인 요청 실패는 노출로 집계하지 않는다. 개별 카드가 실제로 읽혔는지나 클릭됐는지를 의미하지 않는 목록 단위 노출이다. 위치·이메일·로그인·사용자 ID는 저장하지 않고 목록 ID·장소 ID 배열·생성/표시 시각만 저장한다. 표시 확인은 발급 후 1시간 이내, 이력은 최근 7일을 사용한다.

`EXPOSURE_DATABASE_URL`이 있으면 Supabase PostgreSQL의 `app_private.exposure_lists`를 사용하며 SSL을 필수로 적용한다. 스키마는 `supabase/exposure.sql`로 미리 생성한다. public/anon/authenticated 접근은 허용하지 않고 Data API도 비활성화했다. 연결 비밀번호는 서버 환경변수에만 보관하며 프런트엔드나 Git에 넣지 않는다. Render에서 URL이 없으면 SQLite로 조용히 전환하지 않고 추천 목록 조회에 503을 반환한다. DB 실패 메시지에 연결 문자열을 포함하지 않는다.

Supabase 프로젝트: `busan-full-course-exposure` (`zidcslicgrjgceszlxfz`), 무료 조직. IPv4 세션 풀러 5432를 사용한다. 최초 생성한 비밀번호는 `python scripts/configure_exposure_db.py`로 터미널에서 입력하여 로컬 .env에 저장한다. 특수문자는 자동 URL 인코딩된다. 로컬 Python은 `python -m pip install -r backend/requirements.txt`로 PostgreSQL 드라이버를 설치해야 한다. Docker 배포는 requirements를 자동 설치한다. 공개 배포는 Render 서버 환경변수 `EXPOSURE_DATABASE_URL` 등록과 해당 코드 배포가 모두 필요하다.

확인된 노출 이력은 대시보드용으로 유지한다. 미표시 발급 목록만 1시간 후 다음 목록 발급 시 정리하고, 순환 계산에는 최근 7일만 반영한다. 로컬 개발에서 URL이 없으면 기존 SQLite `backend/var/exposure.sqlite3`를 사용한다. `EXPOSURE_DB_PATH`로 위치를 바꿀 수 있다. 기존 SQLite 기록은 자동으로 원격 DB로 복사하지 않는다. Supabase 무료 프로젝트는 비활성 기간에 일시 중지될 수 있으므로 발표 전에 상태를 확인한다.

여러 서버가 하나의 PostgreSQL 기록을 공유할 수 있으나 동시 요청은 표시 확인 전 같은 순서를 받을 수 있다. 공개 요청을 반복하는 봇의 인위적 노출 증가를 방어하는 기능은 포함하지 않는다.

검증: 미확인 목록 미집계, 중복 확인 1회 집계, 120초 경계, 최근 7일 만료, 선택 순서 보존, 전체 시간·복귀·출발지 20분 제약. 현재는 노출 집계/순환 구현이며 상생 효과·사용자 만족을 검증한 결과는 아니다.
