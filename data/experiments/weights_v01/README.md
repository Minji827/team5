# 가중치 v0.1 실험

서비스 입력인 `data/processed/fin/places.csv`는 변경하지 않는다.

## 고정 조건

- 표본 40곳: 식당 17 / 카페·디저트 17 / 관광명소 3 / 쇼핑 3.
- 카테고리별 난수 시드 `20261023:카테고리명`, 장소 ID 정렬 후 행정동별 무작위 섞기와 순환 추출. 같은 원본이면 같은 표본이 재현된다.
- 식당·카페는 각각 광복동 5곳, 나머지 남포동·대청동·부평동 4곳씩 배정한다. 관광명소·쇼핑은 보유 장소가 있는 동을 순환해 3곳씩 추출한다.
- 거리 가중치를 비교할 식당·카페에 표본을 집중한 불비례 층화표본이다. 관광명소·쇼핑은 계산 점검용이며 카테고리 전체 품질을 추정하지 않는다.
- 출발지: 카카오 장소 검색으로 확인한 남포역 부산1호선. 출입구별 차이는 반영하지 않는다.
- 도보시간: TMAP 보행자 경로의 초 단위를 60으로 나눈 값. 20분 초과는 모든 카테고리에서 제외한다.
- 보정 강도 m=20은 초기 실험값이며 검증된 최적값이 아니다.

## 파일과 실행

- `sample.csv`: 고정 표본, 출발 좌표, 실제 경로 기반 예상 도보시간, 평점 입력란.
- `scores.csv`: 계산 결과. 평점이 없으면 점수·순위를 비워 둔다.
- `google_place_matches.csv`: 원본 장소 ID·원본 상호·카테고리·Google place ID·매칭 상태. Google 상호·주소·평점·리뷰 수는 저장하지 않는다.

프로젝트 루트에서 실행:

```powershell
python scripts/weight_experiment.py check
python scripts/weight_experiment.py score
python scripts/google_weight_preview.py
```

`prepare`는 위 배분으로 표본을 재현한다. 출발지·장소 좌표가 같은 기존 표본의 도보시간은 재사용하며, 새 장소만 조회한다. 평점이 입력된 장소가 표본에서 빠지면 덮어쓰지 않고 중단한다.
평점 자료를 확보하면 `sample.csv`의 `rating`, `review_count`, `rating_source`에 저장 가능한 자료만 입력하고 `score`를 실행한다. 평점 1~5, 리뷰 수는 양의 정수이며, 0건·미확보는 미평가로 남긴다.
Google Places 평점의 CSV 보관을 전제로 하지 않는다. API 원문이나 키를 이 폴더에 저장하지 않는다.
정책: https://developers.google.com/maps/documentation/places/web-service/policies

Google 실시간 미리보기는 40곳을 조회해 이름 유사도 0.9 이상·좌표 거리 200m 이내의 유일 후보만 자동 연결한다. 이는 보수적인 자동 검토 기준이며 정답을 보장하지 않는다. 동일 Google ID가 여러 원본에 연결되면 검토로 돌린다. 평점과 리뷰 수는 실행 중에만 사용하고 상위 점수는 터미널에 표시한다. 실행 종료 뒤 `sample.csv`·`scores.csv`의 평점 칸은 그대로 비어 있다. 재실행은 API를 다시 호출하며, 연결된 장소는 저장한 place ID로 조회한다. 애매한 후보·검색 실패를 평점 0으로 처리하지 않는다.

## 계산

- C: 해당 카테고리에서 평점과 양의 리뷰 수가 확보된 표본들의 평점 산술평균. 현재는 표본 평균이므로 모집단 평균이 아니며, 자료 수가 적으면 불안정하다.
- B = (n×R + 20×C) / (n+20)
- Q = (B−1)/4
- D = max(0, 1−출발지부터 도보분/20)
- 식당 = 0.75Q + 0.25D
- 카페·디저트 = 0.70Q + 0.30D
- 쇼핑·관광명소 = Q
- 카테고리 안에서만 순위를 비교한다. 리뷰 수는 B에 이미 반영하므로 별도 로그 점수를 더하지 않는다.

현재 결과는 장소 점수 실험이다. 방문 순서, 다음 구간 도보시간, 체류시간과 총 여행시간을 포함한 완성 코스의 평가는 별도이며, 서비스에는 아직 반영하지 않았다.
